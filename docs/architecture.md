# Architecture and security boundaries

The deployment runs one unprivileged container on a dedicated Ubuntu VM. Docker Compose restarts it after failures and the VM starts automatically. The container runs current Browser Use Python, a persistent visible Chromium profile, Xvfb, and a localhost-only noVNC viewer. On startup it opens the official game even when the agent is idle. FastAPI provides start, pause, resume, stop, status, and read-only Ollama discovery. It has no Docker socket, host shell, arbitrary file tools, or browser developer evaluation action. Save data, profile, checkpoints, screenshots, and action records live in host bind mounts.

The Browser Use WebUI repository was evaluated and rejected for this deployment: its pinned application uses an older Browser Use dependency and its default Compose file exposes browser debugging/VNC ports broadly and requests `SYS_ADMIN`. The current Browser Use Python library supports local Ollama, persistent profiles, screenshots, bounded runs, pause/resume/stop, and excluding actions, so the deployment uses that library with a small local control surface.

Browser navigation is restricted to the official game domain by both Browser Use's allowed-domain feature and the agent's reduced tool registry. The initial browser action is ordinary navigation. The model may use visible UI and documented in-game Netscript only. It receives no host shell, arbitrary file read/write, browser `evaluate`, browser debugging port, Docker socket, or unrestricted outbound browser navigation. The container has no added Linux capabilities and enables `no-new-privileges`.

The existing Browser Use controller exposes a small game-specific tool set for UI observation, visible progress verification, one-shot dialog dismissal, terminal commands and script execution, and allowlisted documentation retrieval. When the restricted Remote API is configured, model-authored scripts are read or deployed through that bridge and verified by read-back plus live RAM calculation. Generic index-based clicks, arbitrary text entry, browser navigation, and browser evaluation are removed from the gameplay tool registry. Terminal access uses the documented Alt+T shortcut and reacquires the visible input after each transition. These helpers do not read game objects, execute page JavaScript, change saves, or supply gameplay strategy; the model remains responsible for deciding actions, reasoning about errors, and writing Netscript.

Each session automatically receives the compact version-aware core guide in `docs/agent-game-guide.md`. `game_help` and `game_troubleshoot` retrieve allowlisted detail from the tool and troubleshooting guides only when requested. Exact Netscript signatures come from the connected game's official Remote API definitions. The custom Browser Use system prompt uses one consequential action per step, verifies returned tool results, and stops after the same failed action repeats without visible change. Checkpoints preserve concise tool error summaries and counts, while the next session reloads the core guide.

The dashboard and noVNC are bound to guest loopback. The firewall permits inbound SSH from the configured management CIDR only; outbound access is needed for the official game and local inference endpoint. Reach them by SSH forwarding. noVNC starts view-only; deliberate human interaction requires setting `VNC_INTERACTIVE=1` in the VM's private environment file and recreating the service. A background watcher checks only completed game UI `.json.gz` downloads, verifies the gzip stream, and archives them separately from the active browser profile with bounded retention.

Model host, model name, and node label are supplied via the ignored private `.env` file. Endpoint failover is not configured until latency, reliability, and compatible models have been tested. Runtime logs and checkpoints are bounded; the browser profile is durable. Game-native export and restore still require end-to-end validation in the running game UI.

The restricted Bitburner MCP Remote API bridge runs as a sidecar sharing the agent container's network namespace. Both its REST and WebSocket listeners bind to loopback, there are no published bridge ports, and its REST calls require a private bearer token. A server-side allowlist exposes only `getFile`, `pushFile`, `calculateRam`, and `getDefinitionFile`; file methods accept only simple `.js` filenames on `home`. Save reads, game/server enumeration, deletion, bulk file reads, and convenience file routes are blocked at the bridge. Request logs omit script contents. Browser Use remains the gameplay controller and is still required to run scripts and inspect results through the game UI.

An explicit emergency stop deletes the saved auto-resume objective so a future service restart cannot undo that operator action. An unplanned interruption leaves the objective in place for startup recovery when `AUTO_RESUME=1` is enabled.
